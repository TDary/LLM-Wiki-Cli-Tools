> 与 Claude Code / AI Agent 交互时的提示词模板

## 一、摄入内容

### URL 摄入

```

```

```

```

```
读取这个 URL，提取其中的实体和概念，创建对应的 wiki 页面：https://example.com/post
```

### 文件摄入

```
把这个文件的内容整理到 wiki 里：/path/to/document.md
```

```

```

### 批量摄入


### 刷新原始资料

**快速刷新（新增 + 删除一起处理）：**

```
执行 wiki refresh，处理所有新增和删除的原始资料
```

```
刷新一下 wiki，新增的提取知识，删除的清理引用
```

**只处理新增文件：**

```
看看 raw/ 有没有新文件需要处理
```

```

```

**只处理删除的文件：**

```

```

```
帮我检查一下哪些 wiki 页面引用了已删除的原始资料，直接清理掉
```

**带确认的精确控制：**

```
先运行 refresh 检查，如果没有问题再 refresh --apply 执行清理。新增的文件按 ingest 流程提取知识。
```

**详细指令（适合首次或复杂场景）：**

```
执行 wiki refresh：
1. 检查 raw/ 有没有新增文件，有的话提取知识并创建 wiki 页面
2. 检查有没有被删除的原始资料，清理失效引用，需要归档的标记归档
3. 完成后汇报处理结果
```

## 六、工作流示例

### 示例 1：阅读论文并提取知识

```
用户: 帮我把这篇论文的核心内容提取到 wiki：https://arxiv.org/abs/2301.00001

AI:
  1. ingest --url https://arxiv.org/abs/2301.00001  → 保存到 raw/
  2. 读取论文全文
  3. 识别出：Transformer 模型、自注意力机制、多头注意力
  4. 创建：
     - concepts/self-attention.md
     - concepts/multi-head-attention.md
     - 更新 concepts/transformer.md（如已存在）
  5. 交叉引用所有相关页面
  6. 更新 log.md

用户: 好的，再帮我看看 wiki 里还有哪些关于注意力机制的内容

AI:
  1. search "attention"  → 找到相关页面
  2. 读取所有相关页面
  3. 综合回答：列出所有相关内容和它们之间的关系
```

### 示例 2：知识库整理

```
用户: wiki 有点乱了，帮我整理一下

AI:
  1. health  → 健康检查
  2. 列出问题：3 个断链、2 个孤立文档、5 个无标签页面
  3. 询问用户：要自动修复吗？

用户: 断链自动修复，其他的看看具体情况

AI:
  1. fix --apply  → 修复断链
  2. orphans  → 列出孤立文档
  3. 建议：这两个页面可以合并到 concepts/transformer.md

用户: 好的，合并吧

AI:
  1. 读取两个孤立文档内容
  2. 合并到 concepts/transformer.md
  3. archive 两个旧页面
  4. 更新所有引用
```

### 示例 3：创建对比分析

```
用户: 帮我对比一下 GPT-4 和 Claude 3.5，创建一个对比页面

AI:
  1. search "GPT-4"  → 找到相关内容
  2. search "Claude"  → 找到相关内容
  3. 读取所有相关页面
  4. 创建 relations/gpt4-vs-claude.md，包含：
     - 性能对比表
     - 价格对比
     - 适用场景
     - 优缺点
  5. 更新所有相关页面的 wikilinks

用户: 加上 Gemini 的对比

AI:
  1. search "Gemini"  → 找到相关内容
  2. 更新 relations/gpt4-vs-claude.md → relations/gpt4-vs-claude-vs-gemini.md
  3. 补充 Gemini 的对比数据
```

### 示例 4：批量处理笔记

```
用户: ~/notes/ 目录下有一堆笔记，帮我整理到 wiki 里

AI:
  1. ls ~/notes/  → 列出所有文件
  2. 读取每个文件，识别主题
  3. 创建 manifest.json
  4. ingest --manifest manifest.json  → 批量导入
  5. 为每个笔记创建对应的 wiki 页面
  6. 建立交叉引用

用户: 有些笔记是重复的，帮我合并

AI:
  1. 比较所有导入的笔记
  2. 找出内容重叠的页面
  3. 建议合并方案
  4. 用户确认后执行合并
```

### 示例 5：刷新原始资料

```
用户: 我往 raw/ 手动放了几篇文章，帮我处理一下

AI:
  1. refresh  → 检测新增文件
  2. 输出：发现 3 个新增原始资料
  3. 逐一读取每个新文件
  4. 为每个文件提取实体、概念、关系
  5. 创建对应的 wiki 页面（含 frontmatter + wikilinks）
  6. 更新 log.md

用户: 之前有篇 raw/deprecated.md 我删掉了，wiki 里有引用吗？

AI:
  1. refresh  → 检测已删除文件
  2. 输出：raw/deprecated.md 被引用于 entities/old-project.md（唯一来源，内容为直接摘要）
  3. refresh --apply  → 清理引用 + 标记 archive_suggested: true
  4. 向用户建议归档 entities/old-project.md
  5. 更新 log.md
```

## 七、提示词技巧

### 1. 明确指定操作

```
❌ "帮我看看 wiki"
✅ "检查 wiki 的健康状态，列出所有断链"

❌ "处理一下这篇文章"
✅ "把这篇文章的核心知识提取到 wiki，创建实体和概念页面"
```

### 2. 指定输出位置

```
❌ "创建一个页面"
✅ "创建一个概念页面 concepts/prompt-engineering.md"

❌ "归类一下"
✅ "把这部分内容放到 entities/ 目录"
```

### 3. 指定关联关系

```
❌ "添加一些链接"
✅ "确保这个页面至少有 2 个 [[wikilinks]] 指向其他页面"

❌ "关联起来"
✅ "在 concepts/transformer.md 和 concepts/attention.md 之间建立双向引用"
```

### 4. 分步骤请求

```
❌ "把所有内容都整理好"（太模糊）

✅ 分步骤：
1. "先检查一下 wiki 的健康状态"
2. "修复所有断链"
3. "把孤立文档关联起来"
4. "生成最新的索引"
```

### 5. 提供上下文

```
❌ "更新一下"
✅ "更新 concepts/llm.md，补充 2025 年的最新进展，参考 raw/llm-2025-report.md"

❌ "添加信息"
✅ "从 raw/interview-transcript.md 提取关于 OpenAI 的信息，添加到 entities/openai.md"
```

### 6. 搜索加速

当 wiki 文档较多时，可以先生成索引再搜索，速度更快：

```
先生成 wiki 索引，然后用索引加速搜索 "performance"
```

> 注意：索引使用词级匹配，中文子串搜索（如"渲染"匹配"渲染管线"）建议用普通搜索。

## 八、常用组合命令

### 日常维护

```
帮我做一次完整的 wiki 维护：
1. 健康检查
2. 修复断链
3. 归档过期内容
4. 更新索引
```

### 内容整理

```
帮我整理 wiki 的内容结构：
1. 检查所有页面的 frontmatter 是否完整
2. 找出没有标签的页面，向用户建议标签后补充（标签需人工审核）
3. 找出孤立文档并建立关联
4. 把超过 200 行的页面拆分
```

### 知识补全

```
分析 wiki 的知识覆盖情况：
1. 列出所有主题和它们的关联关系
2. 找出知识空白点
3. 建议需要补充的内容
4. 基于现有资料创建缺失的概念页面
```
